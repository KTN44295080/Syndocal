# Lighting FX Acceptance

Updated: 2026-07-23

## Implemented tranche

The existing ordered effect stack now has a seven-family quick-start library aligned to common lighting workflows:

| Library family | Current presets | Runtime primitive |
|---|---|---|
| Colour | Colour Spectrum | Multi-stop Color engine with continuous RGB/HSV interpolation |
| Chaser | Chase | Independent ordered-step Chaser engine |
| Move | Circle | Independent paired Pan/Tilt Move path |
| Value | Pulse, Shared, Flash, Random, Perlin | Legacy LFO quick looks; independent Value editor is available from the family/type control |
| Curve | Curve Saw | Independent Cubic Hermite channel function |
| Mappings | Wave, Ball, Fan | Independent fixture-order Mapping function |
| Colour Mappings | Colour Chase | Independent 2D RGB16 media mapping engine |

The chooser uses nine keyboard-focusable family buttons with `aria-pressed` state. The full library contains 13 cards. Colour and Colour Mapping presets cannot load their embedded compatibility target: both frontend and Tauri require an explicit current fixture, group or map selection. Both are whole-fixture targets, do not ask the operator to choose one scalar attribute, and reject video-layer parameter targets. Wave, Ball and Fan likewise require an explicit lighting target and cannot be retargeted to video.

Static Position programming and dynamic Move FX are separate acceptance boundaries. The installed Daslight screen verified locally was the STATIC Position scene `Moving-Pos > Center-Up (2)`; it does not prove any Move runtime behavior. Daslight's official manual defines the Move boundary as editable Pan/Tilt path shapes and points, path translate/resize/rotate, Absolute/Relative operation and live direction/phase/size controls. Syndocal now meets that software boundary with an independent Move runtime and editor. Circle uses the independent Move runtime; Fan is now a static fixture-order Mapping recipe and is not evidence for Move-path behavior.

`EffectKind::Color` is an independent production runtime, preset and project body. It supports two to eight ordered stops, Cycle/Bounce/Sequence/seeded Random algorithms, RGB/HSV-shortest/HSV-longest interpolation, free or beat-synced period, phase, fixture spread and the existing ordered Override/Add/Multiply stack semantics. Add and Update wait until the published snapshot contains the mutation; failed publication rolls the change back instead of allowing Undo/history to race an unpublished effect.

Fixture bindings are compiled when fixtures are patched. A color is evaluated once per effect/fixture/tick and reused for all its components; RGBW/CMY/HSV conversions are enabled per binding so ordinary RGB and wheel fixtures skip unused transforms. Supported software mappings are complete RGB/ColorAdd triplets, RGBW with minimum-channel white extraction, complete CMY, complete HSV/HSB, and color wheels with at least two parseable hex or named-color physical slots (nearest slot in OKLab). Static/shake ranges for the same physical slot remain addressable but count once for support/ranking. Secondary wheels use only an explicit Open/Clear/White or near-white slot as neutral. Mixed groups retain supported fixtures and skip unsupported ones; a new target with zero compatible fixtures is rejected, while an existing group-target effect survives a temporary zero-target state and rebinds after group/patch recovery. Valid GDTF CIE xyY metadata for three to sixteen visible linked emitters enables a command-time non-negative calibrated model whose fixed RGB-cube anchors are interpolated in the 44 Hz path. Amber, Lime, UV and warm/cold-white outputs outside that calibrated model are deliberately held at zero rather than receiving guessed values; a UV emitter with omitted GDTF `Color` is retained as metadata but is not synthesized into visible output.

`EffectKind::Chaser` is also an independent production runtime, preset and project body. Its ordered steps can address fixtures, hierarchical groups or explicit gaps and can scale one to sixteen independently ranged feature attributes. Forward, Reverse, Bounce and seeded Random traversal share deterministic engine/UI ordering; Pixels on, Wings, duty, Fading/Overlap, Size, Phase and fixture spread are live-editable, with free-time or beat-synced step clocks and the existing Override/Add/Multiply stack modes. Mixed fixture selections retain each feature on compatible fixtures, while unsupported fixture/feature pairs are skipped. The runtime precompiles fixture/step levels and feature bindings, caches one normalized step level per fixture/effect/tick, and avoids allocation in the per-attribute hot path.

`EffectKind::Value` is now an independent production runtime, preset, project body and editor. It drives one scalar attribute from an operator-drawn envelope of 2 to 32 strictly-increasing `(position, value)` points with Step, Line or centripetal Catmull-Rom Smooth interpolation, Forward/Reverse/Bounce traversal, free-time or beat-synced clocks, phase, fixture spread and the existing Override/Add/Multiply stack modes. Absolute mode maps the envelope into the low..high range; Relative mode applies a bipolar offset around the incoming value (0.5 means no change). The envelope is compiled once per resolution, evaluated once per effect/fixture/tick via a per-target cache, and avoids allocation in the per-attribute hot path. Add/Update wait for snapshot publication and roll back on contention; dormant group targets survive a zero-compatible-fixture state and rebind after patch/group recovery. The legacy Pulse/Shared/Flash/Random/Perlin quick-look files remain LFO presets and are not presented as Value-body evidence.

`EffectKind::Curve` is an independent production runtime, preset, project body and editor. Two to 32 points carry position, value and separate finite in/out tangents; command-time compilation produces a Cubic Hermite channel function. Forward/Reverse/Bounce, Absolute/Relative, free/beat timing, phase, fixture spread and stack blending match the scalar production paths. Cue-owned parameters and rack previews preserve the authored tangents.

`EffectKind::Mapping` is an independent fixture-order scalar runtime, preset, project body and editor. Explicit selection targets preserve their authored fixture ID order; group targets expand deterministically in patch order. Sine/Cosine/Triangle/Saw/Square/Random/Perlin functions support Forward/Reverse/Bounce/Static traversal, Absolute/Relative output, free/beat timing, phase, fixture spread, 0.25–16 repetitions and stack blending. Target indices and one cache cell per resolved target are built on commands/rebuild, so the per-attribute tick path performs no target search or allocation. Wave, Ball and Fan now deserialize as Mapping bodies. This closes fixture-order Mapping only; it is not image/text/video RGB sampling and is not Colour Mapping parity.

`EffectKind::ColorMapping` is an independent 2D colour runtime, preset, project body and editor. The editor converts a local image or rendered text into one embedded RGB16 frame and bounds local video extraction to 2–64 embedded frames; each raster axis is limited to 64 cells. Targets may carry explicit fixture/beam matrix cells or follow fixture stage X/Z positions normalized when the command is resolved. Playback supports Forward/Reverse/Bounce, free or beat clocks and phase. UV offset/scale/rotation combine with Clamp/Repeat/Mirror wrapping and Nearest/Bilinear sampling. Pixel decode, colour bindings, sample indices/weights, target indices and one evaluation cache per target are built on add/update/rebuild. The 44 Hz path selects one frame and samples at most four precomputed pixels without file decode, allocation or fixture search. The built-in Colour Chase is now an eight-frame `ColorMapping` body rather than a Color Sequence alias.

`EffectKind::Move` is an independent production runtime, preset and project body that evaluates Pan and Tilt as one atomic pair. It supports editable open/closed paths, exact line and centripetal Catmull-Rom smooth interpolation, path translate/scale/clockwise rotation, Absolute/Relative coordinates, Forward/Reverse/Bounce traversal, free/beat clocks, phase and fixture spread. Paths compile to an arc-length lookup table; tick evaluation uses binary search plus one cached pair per effect/fixture/tick without hot-path allocation. Add/Update wait for snapshot publication and roll back on contention. Dormant group targets survive zero-compatible-fixture states and rebind after patch/group recovery. Blend is deliberately restricted to Override until paired-axis composition semantics are separately designed and accepted.

The Chaser inspector keeps a reactive 24-cell preview, ordered step editor, gap insertion, feature coverage, min/max ranges and movement/replacement actions in the center pane. Step editing is paged at eight rows and the live rack at ten effects so large drafts and stacks do not expand the desktop. Changing Type while editing intentionally starts a new draft rather than replacing a different effect kind in place; engine and Tauri guards independently reject wrong-kind updates.

Cues now store a selective list of `CueEffectTarget { effect_id, enabled }` values. GO, Back, direct trigger, pre-wait completion and follow progression apply each listed state once and leave unlisted Effects unchanged. `Effects Only` can create a pure Effect Cue; scoped Lighting, Video, fixture and group updates replace only eligible Effect entries while preserving out-of-scope Recall. Deleting an Effect removes its Cue references, legacy files default to an empty list, and the user-facing `.sdc` loader rejects unknown or duplicate references instead of silently changing a show. Effect enable, Cue creation, Details, Look update and Recall-only save acknowledge the published snapshot before the UI commits Undo history; Details applies metadata, Parts, Mark and MIB atomically. The Cue editor deliberately separates `Save Details`, `Save Recall` and `Update Look` so a metadata edit cannot recapture a live look and a Recall edit cannot overwrite fixture/video targets.

The former vertically serialized Library/Form/Graph/Stack view has also been replaced with a dedicated full-window production desk. Effects mode now hides the unrelated live overview and generic stage, and keeps `Effect Library | Inspector | Live Rack` visible as three continuous panes. Recipe selection/actions and effect range/apply actions are fixed to the bottom of their panes; only pane contents scroll. Stack/Graphs are explicit rack tabs. The visual system uses neutral graphite surfaces, thin dividers and the Syndocal orange state accent rather than copying Daslight colours or controls.

## Viewport validation contract

The design sign-off browser viewport is 1920x1080. Information hierarchy, editor density, pane balance and screenshots are judged there first. Native Windows acceptance is separate: this workstation has a 1920x1032 work area, a 1920x1009 decorated Tauri client while maximized, and an exact 1920x1080 client under F11 fullscreen. The 2048x1152 browser run is an extended-width ceiling regression. The 1366x768 and 1280x720 runs are mandatory compact fallbacks that prove containment and reachable pane-local scrolling; they are not substitutes for either large-window review and must not be used alone to call a desk well designed.

`check:viewport` starts its headless browser at 1920x1080 and runs the 1920x1080 primary gate, 1920x1032 measured-work-area fixture, 2048x1152 ceiling, 1366x768 fallback and 1280x720 fallback in that order. The 1920x1032 run remains a browser fixture and is not native evidence. When `SYNDOCAL_VIEWPORT_SCREENSHOT_DIR` is set, the default evidence set captures both large browser fixtures; `SYNDOCAL_VIEWPORT_CAPTURE_ALL=1` is an explicit diagnostic override for compact/ceiling screenshots.

The production Type control now exposes `Move`, and the complete Move editor viewport gate passed on 2026-07-13. At all five viewports it requires the dedicated path desk, inspector, canvas and point operations to remain horizontally contained, with both the outer Inspector form and point list able to reveal their last controls. At 1920x1080 it additionally requires a real two-column path/inspector layout, a minimum useful canvas, and at least 98% surface/column area coverage with no measurable unused right or bottom strip. Compact fallback stacking and internal scrolling are allowed; a one-column 1920x1080 result remains a failure.

## Competitive boundary

All seven Colour, Chaser, Move, Value, Curve, fixture-order Mapping and 2D Colour Mapping families now have real independent saved bodies, validation, runtimes and editors rather than display aliases. Cue-owned Effect states also have an optional same-ID cross-Cue fade with continuous/discrete output policies. Profile-driven calibrated multi-emitter mixing is complete in the software path and fails closed when metadata is absent. Multiple Value quick looks remain legacy LFO presets, rack-operation breadth and representative physical/external-visualizer acceptance are pending. Therefore the independent-engine, Cue-transition and calibrated-emitter software gaps are closed, but the full library must **not** yet be described as Daslight 5 FX parity.

Remaining engine work:

1. Colour fidelity: GDTF CIE xyY calibrated additive mixing is complete. Remaining work is measured spectral/physical acceptance, CTO/CTB policy and representative RGBW/CMY/wheel/output-node comparison; metadata-free extra emitters intentionally remain zero.
2. Cue modulation: Effect ON/OFF recall, source-linked reusable Scene Blocks and direct Cue List same-ID Effect state fade are complete. Scene Block loop/jump, persistence, publication and full-screen evidence are tracked separately in `qa/SCENE_BLOCKS_ACCEPTANCE.md`; block overlap/fade remains a separate timeline model.
3. Move field acceptance: the independent software path is complete; verify Pan/Tilt direction, limits, invert/swap, Absolute/Relative output, beat timing and a one-hour mixed DMX load on representative moving fixtures.
4. Curve/Value: both independent runtimes and editors are complete. Remaining: migrate or replace the legacy Value-family LFO quick looks, add rack-level macro/live modulation controls, and obtain representative physical-output acceptance.
5. Mappings: fixture-order Mapping and independent Colour Mapping are complete in software, including bounded image/text/video RGB sampling, matrix cells, UV transforms and spatial preview. Remaining: representative RGB/RGBW/wheel matrix acceptance through the Art-Net external-visualizer path and physical fixtures, plus any expanded codec/resolution policy beyond the bounded embedded-frame contract.
6. Rack operation: named racks, multi-select bypass, reset/hold, macro controls and rack virtualization remain. Release 44 Hz/p95/p99 ordinary, transition and calibrated mixed-stack benchmarks exist; the controlled-host rerun and venue soak remain acceptance work.
7. Chaser field acceptance: the software path is complete, but real-fixture direction/order, beat timing, mixed-attribute output and one-hour DMX load still require representative rigs. The editor preview is deterministic parameter visualization, not an engine-telemetry playhead.

Only after the remaining Scene Live, rack-operation and representative fixture/external-visualizer gates pass can overall FX parity be considered closed. See `qa/CALIBRATED_MULTI_EMITTER_ACCEPTANCE.md` for the closed software colour model and its deliberately separate physical boundary.
