# Effects and shaders: find, understand, audition, apply (Task 12)

Updated: 2026-10-19. Base: `96bac1a0`. Status: uncommitted working tree, for review.

## Why (the owner's complaint)

The owner finds effects and shaders hard to understand, "even in SynapseRack". The
competitive review (`qa/COMPETITIVE_REVIEW_2026-10-16.md`, item 4) found that layer FX,
group FX and output FX are reached by different routes (built-in selector for a layer,
file import for an output), that the target scope is not conspicuous, and that there is no
safe audition, preset or bypass story. `qa/VJ_PERFORM_UI_2026-10-18.md` reserved the
Inspector's Browser tab for this work.

| Complaint / review finding | What changed |
| --- | --- |
| "I cannot tell what an effect does" | Every effect is a card: thumbnail rendered on a standard test image, name, category, one-line Japanese and English description (written for the 14 built-ins; ISF `DESCRIPTION`/`CATEGORIES` for imports, else "Imported shader"). |
| "I cannot find one" | Search over name, category and description; category filter; the browser is in the Perform Inspector and, from the Video workspace, in an Effect browser dialog. |
| "Where does it go?" (scope not conspicuous) | The header always reads `Add to: Layer N · name`. A row drop names its destination in a confirmation. |
| "Is it safe during a show?" | `Try` shows the effect on Preview only. `Add` is labelled LIVE. Removal needs a second click. Live edits keep a one-step Undo. |
| "The parameters are cryptic" | Human labels (ISF `LABEL`, else humanised name), value with unit, range, Reset default, colour picker, 2D pad for points, Randomize (bounded, undoable), named presets saved in the project, built-in presets. |
| "A shader failed and I do not know why" | Plain-language reason in Japanese and English on the card and in the media-health area, with the line or input when known, what to do, and the raw engine text one disclosure away. |

## Design

### Effect browser (`VideoEffectBrowser.tsx`, `fxCatalogModel.ts`, `fxThumbnail.ts`)

* Entries: the 14 built-ins (parsed once from `crates/video/src/builtin_isf.rs`, so the list
  cannot drift) plus every imported ISF found in layers, scoped chains and presets, plus
  rejected imports. Imports are deduplicated by normalised source.
* Card states: `Ready to add`, `Already in this layer`, `Unavailable` (rejected or failing at
  runtime). Unavailable cards cannot be added or tried.
* Thumbnails: one shared 160x90 WebGL context renders the shader once on a fixed test image
  with its default values, only when the card scrolls into view, cached by source, with a
  labelled fallback for complex, multi-pass or non-compiling shaders. It never touches a
  layer or an output.
* Apply: Add button, Enter or double-click on the card, drag onto a layer row (confirmation
  names the destination and says LIVE) or onto the FX tab. Drag payloads carry only an
  in-memory card id, never shader text. All adds use the existing ticketed chain commands.

### Parameters, presets, randomize (`VideoFxParameterEditor.tsx`, `fxParameterModel.ts`)

One editor serves the Perform FX tab and the Video workspace. Ranges, defaults and values
come from the validated runtime summaries; ISF `INPUTS` only supply the human `LABEL`.
Units are shown only where the shader maths is known (percent for 0-1 floats, degrees for
Rotate and Kaleidoscope, Hz for Strobe and Glitch Shift, x for Zoom). Typed angles use
degrees. Colour: native picker, hex plus opacity readout. Point: 2D pad plus X/Y sliders.
Randomize draws inside each declared range; Undo goes through the exact-head project Undo.
Presets are the project's existing `effect_presets`; two built-in recipes ship for each
parameterised built-in.

### Safe audition (Preview, then Take; A/B)

Investigation (HEAD `96bac1a0`): P staged a layer's source and independent playhead, but the
Preview frame was rendered from the *current engine snapshot* of that layer, including its
authored effect chain (`render_live_video_monitor_frame`, Preview branch, with
`vj_preview_render_snapshot` cloning the layer; its one-layer snapshot has empty
`effect_chains`). So an FX edit on a P-staged layer reached Program as well as Preview. The
first run of this task therefore shipped a UI-only fallback (explicit LIVE warning, one-step
undo, live A/B). That fallback is still what the Full FX editor and the Add button do, and
they stay labelled LIVE.

This run adds a small, contained native seam so the audition is genuinely isolated:

* `VjPreviewTransportSession.effect_audition: Option<Option<VideoIsfEffectSummary>>`
  (`main.rs`, struct near line 13899). `None` renders the authored chain, `Some(None)` an
  empty chain, `Some(Some(chain))` the draft. It is runtime-only: not in `.sdc`, Recovery or
  Undo, and not serialised (the summary exposes only the boolean `effect_audition`).
* `set_vj_preview_effect(layer_id, active, effect)` (`main.rs` ~80548) validates with the
  same `sanitize_video_isf_effect` as the live layer setter, requires the layer to be the
  staged Preview layer, and bumps the transport generation (`set_effect_audition_at`, ~14073),
  so a frame rendered with the previous chain is returned as busy instead of published.
* The only reader is the Preview branch of `render_live_video_monitor_frame`
  (`transport.effect_audition()`, ~80746), applied to a cloned layer in
  `vj_preview_render_snapshot` (~80585). Program, output windows, recording, thumbnails and
  Take read nothing from it.
* Lifecycle: restaging the same layer and source keeps it; staging another layer, Clear, a
  replaced source, a removed layer or a project reset ends it.
* `get_builtin_video_isf_effect(preset_id)` is a read-only description of a built-in, so an
  audition can be built without writing the effect into a layer.
* Both commands are runtime routes, not project mutations. The pinned inventories were
  updated and re-derived (584 Tauri routes, 504 frontend invokes, new SHA-256 in
  `control_plane.rs`, route-class counts, `check-frontend-command-routing`,
  `check-ai0-source-coverage`).

Frontend (`createFxAuditionSession.ts`, `fxAuditionModel.ts`, `VideoFxAuditionBar.tsx`):
the Perform FX tab shows a green-framed `AUDITION · PREVIEW ONLY` bar. `Try` on a card (or
`Try on Preview` in the FX tab) stages the layer if needed and starts a copy of the live
chain. Everything in the tab (add, reorder, enable, remove, parameters, presets, Randomize,
Undo) edits the copy and is published to Preview only. `A · Current` / `B · Edited` toggles
what Preview shows. `Take to Program` needs a second confirming click and then uses the
existing ticketed `set_video_layer_isf_effect` path (so Undo FX works afterwards); `Discard`
ends it. Take is refused when the live chain changed after the audition began, when Preview
now shows another layer, or when the layer is gone; the draft stays readable. Event controls
are disabled during an audition because they fire on Program. Comparing is also available
live (A/B on the Full FX editor), explicitly labelled LIVE.

### Explained rejections (`fxRejectionExplanation.ts`, `VideoFxProblemsDialog.tsx`)

A rule table maps the real engine messages of `prepare_isf_shader` (syntax or header errors,
unsupported input type, audio, multi-pass or target buffers, forbidden constructs, image
input count, unsafe or duplicate names, invalid defaults, limits) to a title, a detail, an
action, an optional line or input, and the raw text. Lines are derived from the file where
possible (header JSON lines are mapped to file lines). The card shows it; the media-health
bar shows a one-line summary and an `Effect problems` button that opens a dialog listing each
problem with its raw text collapsed.

## Limitations and gaps

* Units: BPM-synced beat units are not offered; Strobe rate is in Hz. Units are only shown
  for built-ins whose maths is known; imported shaders show the raw number (or percent for
  a 0-1 float).
* Reorder is by Up/Down buttons, not drag.
* The category filter is a drop-down of buttons, not always-visible chips, to keep the
  Inspector (about 230 px high at 1366x768) usable; the pane can be maximised.
* Audition needs a Preview-capable layer (local file, still image, generator). Camera,
  screen, NDI and Spout layers cannot be staged (existing contract) and the reason is shown.
* An audition is not carried across a restart or project change by design.
* A rejected import's label is generic (the engine error does not carry the file name).
* Preview runtime faults of an audition chain are not surfaced separately; a rejected chain
  is refused when it is sent.
* Presets are per-stage; chain presets already exist as scoped chain presets in the Video
  workspace and are unchanged.
