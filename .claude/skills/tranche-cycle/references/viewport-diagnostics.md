# Viewport・検証停止の診断

ここにあるのは過去の局所的な障害と診断の手掛かり。常時実行する追加ゲートや、
新しい障害への確定診断ではない。現在のスクリプトと再現条件を確認して使う。

## 実行と証拠

- focused scenarioが本当に実行されたことと終了コードを確認する。存在しない環境変数で
  対象がスキップされた事例があり、PASS行だけでは証明にならない。
- 長いviewport実行は進捗ログと停止を検出できるタイムアウト/監視を用いる。
  完了まで出力を隠すフィルタは避ける。必要性のない全matrixへ拡大しない。
- ハーネスはVite 5173とCDPの既定9227を使う。現在のオプションと占有プロセスを確認する。
  staleプロセスへの接続を避ける `failIfPortOccupied`、所有プロセスの後始末を維持する。
  無関係なポート所有者を終了しない。MSYSのPIDをWindows PIDとして扱わない。
- Chrome 150で重量navigationを繰り返す長寿命セッションが停止した事例がある。
  現行の `recycleBrowser()` と新品プロファイルはその対策。取り除く場合は元の再現条件で
  安定性を確認する。強制終了したブラウザのプロファイルにはロックが残り得る。
- 結果の帰属を比べる必要があれば、所有権を確認した隔離checkoutで同条件のA/Bを行う。
  共有ツリーの変更を診断のためにstash/resetしない。

## UIとハーネスの調査

- DOMの矩形・scroll範囲など、対象受入条件に対応する実測で画像を補完する。
  resize後の画像とDOM測定が食い違う場合はDPR・ズーム・キャプチャ時点も調べる。
  測定だけで画像上の問題を無効扱いしない。
- `app/scripts/profile-marker-click.mjs` はV8 self time、`trace-marker-flip.mjs` は
  layout/styleのトレースを調べる入口。低いJS時間だけではnative layoutを特定できない。
- ResizeObserverでピクセルviewBoxを書き換えるSVGと内容依存のgrid行が循環し、
  過去にレイアウト発振した。ホスト高さと `contain: size layout` で解消した事例があるが、
  現在の寸法依存を追ってから適用する。
- 入れ子の `scrollbar-gutter: stable` は未使用の幅を複数層で消費し得る。
  その要素自身のスクロールと寸法契約を確認し、保険として一律追加しない。
- `check-viewport-containment.mjs` の失敗条件出力を確認する。evaluate用JavaScriptを
  通常のテンプレートリテラル内に書く場合、正規表現のバックスラッシュは外側で
  escapeが必要になる。生成されたコードと対象scenarioの実走で確認する。

## 応答停止の切り分け

CPU時間の増分で計算継続か待機かを分け、必要ならブラウザレベルCDPのflat sessionで
短い `Runtime.evaluate` にタイムアウトを付ける。ページへの別クライアント接続は
既存の自動化と干渉し得る。ダイアログやスレッド待機も証拠を取って切り分ける。
