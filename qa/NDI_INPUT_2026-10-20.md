### Compatibility

Input identity is now the complete, exact, case-sensitive advertised NDI name. Empty, noncanonical whitespace, control characters, over-4096-byte UTF-8 names, and duplicate full names are rejected. Retired short-name and case-insensitive matching cannot silently bind another sender. Existing projects using those selectors must reselect a full name from discovery. No project schema or output-ownership policy was changed.

### Lifecycle and performance boundaries

The registry lock is released before SDK construction and teardown. A 250 ms stop acknowledgement timeout retains the receiver and prevents a replacement until it can be reaped. Final destruction still joins the worker and can block indefinitely if the SDK call or destructor hangs. Finder/capture wait arguments do not bound all SDK initialization/destruction work.

The latest-frame store holds one Arc snapshot; repeated shared render reads reuse decoded pixels. Each new SDK capture still incurs grafton's owned capture copy, RGBA conversion, and one decoded-frame copy per renderer; direct recording snapshots also copy. No throughput, end-to-end latency, allocation benchmark, or hardware performance claim is made. Existing output fences and packaging guards remain in place.

## Unverified acceptance and next action

`cargo check -p syndocal --features ndi --locked` was attempted and blocked in grafton-ndi 0.11.0's build script: the installed NDI 6 SDK header `Processing.NDI.Lib.h` was absent. The feature-enabled application and receiver/decoder integration tests could not compile here. SDK-free loader-policy tests and source/API review do not replace that build.

Missing-runtime startup safety is therefore an implementation claim awaiting native acceptance, not a proven no-crash result. Linux/macOS retain grafton's eager shared-library dependency.
