- `VideoSourceKind::Generator(VideoGenerator)` is an additive externally tagged PascalCase
  serde variant; existing source strings and version-1 projects keep their representation.
  Old projects load unchanged. Older Syndocal versions reject projects using generators as
  an unknown source variant; an Active/Standby pair must run the same version before using one.
- Invalid/future kinds, unknown fields, parameter ranges, contradictory file metadata and
  file hashes on generator assets reject explicitly. No permissive fallback or migration.
- Generated bytes depend only on parameters, output dimensions and layer position in time.
  Q16 interpolation/smoothing, fixed Q15 sine literals and wrapping u32 hashes specify the
  arithmetic; no host trigonometry, wall clock, floating point or RNG enters generated pixels.
  Noise samples `floor(position_ms*30/1000)` and wraps its temporal hash cell explicitly.
- Both frame providers use one RGBA8 implementation. Recording/Display/NDI/Spout consequently
  receive the normal provider result; this is source-path evidence, not observation of external peers.
  Existing opacity, ten blends, transforms, built-in/ISF effects and transitions apply normally.
  RGBA generators retain ordinary GPU composition admission; effects/active transitions retain
  their existing eligibility restrictions.
- Static frames cache by parameters, dimensions, layer and render-input identity. Noise caches
  at 30 Hz and evaluates at an internal longest edge <=512 pixels, expanded deterministically
  to the requested RGBA8 dimensions. Cache bounds: 16 entries / 128 MiB; invalid sizes reject.
  Shared cancellable reads retain cached Arc storage rather than copying a full frame per tick.
  Cancellation checks occur before cache use and between rows; partial frames are not published.
- Source changes retire obsolete generator queues, including the derived blended-output queue
  when either retained Clip Take input changes. Static PTS zero cannot lose to older animated PTS.
- Creation allocates a MediaAsset, default Clip Slot and Layer through the existing published
  media transaction. Parameter edits update the current generator MediaAsset and preserve
  transport/slots/other authored settings; duplicates sharing that asset see the same edit.
  File/live layers cannot be replaced through the parameter-only command.
- Native commands use the existing window/owner/epoch-bound transaction ticket and durable
  history flow. Manifest, frontend facade and canonical control-plane inventory contain both
  routes; external command surfaces keep the same admission/fail-closed policy as other
  layer-source edits. No new bypass or autonomous remote source-authoring capability.
- The existing layer panel creates all three kinds and discloses their parameters. EN/JA copy,
  control sizing and internal scrolling are preserved. Editors read current published parameters
  and disable their native fieldset until publication/refresh completes, preventing lost edits.
